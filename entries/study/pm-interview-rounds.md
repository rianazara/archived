Knowing the round tells you which framework to reach for, which is most of
the value of preparing by structure rather than by question list:

| Round | Question types |
|---|---|
| **Product sense** | design a product, improve an existing one |
| **Analytical** | root cause analysis, guesstimates, problem solving |
| **Execution** | metrics and KPIs |
| **Behavioral** | stakeholder management, conflict resolution |

Why it helps: the same prompt gets a different answer depending on the
round. "How would you improve X" in a product sense round wants user
segments and problem framing; in an execution round it wants the metric
you'd move and how you'd measure it.
