Candidate agents for a PM's own workflow: morning learning, meeting notes,
customer feedback triage, customer interviews, release notes, spec review.

The valuable part is the four questions to answer before building any of
them:

- **Job** — what should it do? One job only.
- **Read** — what will it read? Paste it in or point it at a source.
- **Give back** — what exactly should it return? Specify format, length and
  language.
- **Never touch** — what is it not allowed to do? Start read-only, so it
  suggests and you decide.

Then test on three real examples and fix the prompt wherever it's wrong.
Only put it on a schedule if you actually need it daily or weekly.

"Never touch" and "start read-only" are the two that prevent most regret —
the same instinct as "permissions before autonomy" in
[[seven-layers-of-ai-engineering]]. And scheduling last is right: a daily
agent you don't need is a daily notification you'll learn to ignore.
