The sequence:

**LLMs → agents → RAG → workflows → MCP → multi-agent systems → evals**

Each step maps to one question: how LLMs work, how agents think, how agents
reach knowledge, how they execute workflows, how they connect to tools and
systems, how several collaborate, and how they're evaluated and improved.

The argument for caring about order: frameworks will be replaced, these
layers won't. Learning the concept behind each step transfers whether you
end up building coding agents, research agents, support agents or
AI features in a product.

Consistent with [[seven-layers-of-ai-engineering]], which covers the same
ground with production and observability called out separately. Where they
agree is worth trusting: evals come last in the list but are the thing that
tells you whether any earlier layer works.
